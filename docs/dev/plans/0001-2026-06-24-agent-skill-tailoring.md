## Audit Findings

1. The package is mostly portable, but several skills assume Claude Code vocabulary: `CLAUDE.md`, the `Agent` tool, slash-command flows, and subagent names.
2. The setup skill picks `CLAUDE.md` before `AGENTS.md`. For this stack, `AGENTS.md` should be the default repo loading contract unless a repo explicitly says otherwise.
3. The issue-tracker model is GitHub/GitLab/local markdown/other. Our repos often use repo-native plans, `docs/dev/notes`, policy docs, live tenant artifacts, and sometimes GitHub only as a secondary surface.
4. Code discovery instructions are generic. In repos with CodeGraph or codebase-memory MCP, structural discovery should prefer those tools before grep/read loops.
5. Runtime validation needs stronger local rules: verify real config paths, MCP loading, service state, tenant DB/artifacts, Slack bindings, and browser/runtime evidence when those surfaces are part of the task.
6. The `implement` skill is not exposed by `.claude-plugin/plugin.json` and also says to commit automatically. Do not install or use it as-is.
7. The `handoff` skill saves to OS temp by default. That is useful for transient handoffs, but this stack often needs repo-native durable notes when the user asks for continuity.
8. `improve-codebase-architecture` writes an HTML report to temp and uses Tailwind/Mermaid CDN. That is fine for interactive review, but reports tied to plans should be copied or summarized into repo-native artifacts.

## Tailoring Strategy

Use a local overlay rather than editing upstream first. Keep upstream skills recognizable, then add Codex/workstation rules in either:

- a local wrapper skill, if the skill manager supports overlays cleanly;
- repo-level `AGENTS.md` blocks generated by setup;
- or a fork only after one install/run cycle proves the overlay is too awkward.

## Required Patches Or Overlays

### 1. Codex setup overlay

Create a Codex-specific setup variant or patch `setup-matt-pocock-skills` behavior:

- Prefer `AGENTS.md` over `CLAUDE.md` on this workstation.
- Add a `docs/agents/codex-stack.md` file describing:
  - CodeGraph/codebase-memory MCP preference for structural code discovery.
  - `rg` fallback only for literals, configs, logs, and non-code files.
  - `~/.codex/config.toml`, `codex mcp list`, and `codex mcp get <name>` as live MCP truth surfaces.
  - no automatic commits unless the user explicitly requests commit behavior.
- Teach setup to detect existing repo policy docs under `docs/dev/policies/` and reference them instead of duplicating policy.

### 2. Issue tracker adapter

Add a fifth issue-tracker template: `issue-tracker-repo-native.md`.

It should cover repos where work lives in:

- checked-in plans or roadmap files;
- `docs/dev/notes/`;
- `RUNBOOK.md`, `PROGRESS.md`, `ROADMAP.md`, or repo-specific planning docs;
- tenant/runtime evidence artifacts;
- GitHub/Linear only when a repo explicitly uses them as source of truth.

`to-prd`, `to-issues`, and `triage` should read this template before creating GitHub issues.

### 3. Code discovery adapter

Add a small reference file, `codex-code-discovery.md`, and link it from setup/domain docs:

- Use CodeGraph for structural questions: definitions, callers, callees, impact, traces, focused context.
- Use codebase-memory MCP when the repo advertises it.
- Fall back to `rg` for literal strings, config, scripts, docs, or when MCP tools are unavailable.
- Do not stall if a repo advertises CodeGraph but the tools are not exposed; continue with direct repo reads and note the fallback.

### 4. Runtime proof adapter

Add a `runtime-proof.md` reference used by `diagnosing-bugs`, `tdd`, `triage`, and `improve-codebase-architecture`:

- Prefer a tight pass/fail loop.
- For MCP work, verify both direct CLI/API behavior and Codex-visible loading.
- For Slack/OpenClaw/tenant work, verify real account/channel IDs, tenant DB/artifacts, and runtime config files.
- If docs/manifests disagree with runtime evidence, report the mismatch and prefer runtime proof.
- Stop retrying privilege-gated operations when non-interactive auth/sudo has already failed.

### 5. Handoff policy

Patch or wrap `handoff`:

- Default temp handoffs are fine for transient context transfer.
- If the user asks for a durable note, repo policy handoff, or plan continuation, write where the repo says continuity artifacts live.
- Never put secrets in handoffs.
- Include exact paths, commands run, validation results, and remaining blockers.

### 6. Architecture review scope control

Patch `improve-codebase-architecture`:

- Read `AGENTS.md`, repo policy docs, `CONTEXT.md`, ADRs, and current plan files first.
- Use CodeGraph/context tools before broad manual exploration when available.
- Separate "observed friction" from "speculative refactor."
- For plan-bound work, produce a compact repo note or issue summary after the temp HTML report.

### 7. TDD and debugging defaults

Keep `tdd` and `diagnosing-bugs` mostly intact, with two local additions:

- Prefer the repo's existing test runner and validation scripts before inventing new harnesses.
- Record the exact failing/passing command in the final answer or repo artifact.
